# 渲染稳定性与性能优化

> 更新：2026-10-02。适用：单机、冒险（含测试）、在线共用 UI。
> 本轮不修改技能规则，不降低粒子数量、光效、卡牌清晰度或动画时长。

## 闪烁的原因与修复

频繁状态同步原先会整体替换 Buff、道具、配饰和货币的 HTML。WebP 图片节点被反复移除、重新插入，图标入场动画也会重新开始；旧的延时删除任务还可能覆盖下一次状态，造成短时间反复出现/消失。这不是需要把 WebP 换回 PNG 的问题。

新增 `js/ui/render/runtime.js`：

- `RenderDOM.patchMarkup()` 按稳定标识复用节点，未改变的 src 不重新赋值，只更新文字、层数和可用状态。
- 真正新获得的图标播放入场动画；已有图标只在明确触发事件时闪烁。
- 移除图标仍播放原来的 160ms 退出动画，但不延迟替换整块界面；快速重新获得同一状态时取消旧删除任务、恢复原节点。
- 道具采用“名称 + 同名出现次数”标识，领取/使用前面的道具不会重新创建后面所有图标；实际操作索引单独更新。
- 角色选择页和地图重组时复用相同 src 的已加载图片节点。外层交互节点重新绑定，避免保留过期闭包。

主页相册同样按实际容器宽度缓存布局，连续 resize 合并到一帧；地址栏/键盘仅改变高度时不重建 WebP 切片、不重启圆柱旋转。源图片解码完成后再组合可见相册，原双层曲面样式与旋转时长不变。

## 绘制与动画算法

### 卡牌缓存

`CardStyle` 的牌面、牌背分别使用上限 128 的 LRU 位图缓存。缓存键包含尺寸、颜色、指定色、数字、牌种、战利名称和怪物身份，保证金边、黑边与指定颜色不会混用。每次返回独立 canvas，缓存本身也保留独立位图，调用方不能污染其他牌。

图标按 URL 去重加载，解码完成后增加版本并失效牌面缓存；不把加载中的空图标永久缓存。选中样式由 CSS 保留。

### 稳定手牌

玩家只改变选中状态时仅更新 class/aria，不重建手牌 canvas。NPC 手牌在内容、交互阶段、隐藏抽牌数量等未变化时也不重建，覆盖 1v1 和 1v2。动画仍能显式失效缓存；抽牌隐藏遮罩和飞出源牌隐藏规则保留。悬停说明实时读取当前状态，不使用缓存时过期的 Buff 数据。

### 动画调度与粒子

卡牌飞行、屏幕震动和命中粒子共用 `RenderFrames`，同一批动画只向浏览器申请一次 requestAnimationFrame；每个动画仍可单独取消，播放期间新排入的任务进入下一帧。

命中粒子按真实经过时间计算速度和重力，通过 transform/opacity 移动，不在每帧读写 left/top。原粒子数量、颜色、大小、阴影和 600ms 时长不变，60Hz/120Hz 屏幕得到一致的轨迹。

背景粒子恢复正确的 visibilitychange 生命周期：隐藏时停止，重新可见时继续；不因旧 RAF 标识而永久停掉。移动端工具栏/键盘引起的普通 resize 不再触发整副手牌重画，跨越布局断点时仍重新计算卡片尺寸。

## 状态与库存投影

`CombatState.project()` 先组装必要字段，最后仅深拷贝一次；保持输出与引擎内部数组、事件独立，不产生写回副作用。

战斗道具栏只投影库存名称到只读道具定义，不为每次 UI 更新生成地图、牌堆、商店等完整冒险快照。这里不改存档、网络协议、随机结果或伤害结算顺序。

## 验证与维护

```powershell
node --test game/tests/render-performance.test.js
node game/scripts/check.js --all
```

渲染回归包含图片节点身份、入场动画不重启、快速移除/恢复、道具点击/双击竞争、缓存牌面隔离、共享 RAF、真实时间粒子轨迹、手牌复用和投影隔离。DOM 测试使用本地开发依赖 jsdom（仅测试，不进入静态网站）；缺少该依赖时测试明确标记跳过，不应把跳过当成验证通过。

浏览器人工检查：角色选择、选牌/出牌、冒险挑战测试的 Buff/道具/配饰/货币、道具移除后剩余图标。新增脚本同步到三张入口、script_manifest 和加载顺序检查，更新资源查询版本以避免部署后旧缓存混用。

这轮通过减少重复工作提升性能，没有声称固定 FPS 或百分比提升；具体设备帧率仍需在实际网络与终端上采样。后续新增图标区应调用稳定 DOM 层，不要在每次同步中清空整块容器再添加图片。
