# 统一攻击与伤害结算

更新：2026-10-03。适用：单机1v1、1v2、领主、冒险普通/挑战/Boss与测试、在线对决。

## 结算顺序

1. **打出攻击牌**：移出手牌，确定攻击方与目标，记录出牌事件。技能判定、选牌、选色、资源消耗在此完成；随机判定只产生一次。
2. **攻击修正**：确认道具、配饰、暴击等修正。伤害提示是用于防御决策的预估值，固定加值和倍率在后续重算时保留；赌盘攻击失败锁定为0，不会因状态重算复活。
3. **防御牌与防御技能**：防守方出牌或跳过。反击、回血、抽牌、净化、免疫/反弹只执行一次。搭桥可以继续防御，不提前执行主攻击扣血。
4. **施加攻击附带状态**：仅把标记为 beforeDamage（先状态、后伤害）的Buff/Debuff提交到对应角色。免疫先过滤目标状态；反弹改为施加给攻击者；攻击者自身增益不受目标免疫影响。层数上限在此重新检查。
5. **计算当前状态下的伤害**：状态公式读取此时的灼伤、流血、茂盛等。半伤防御对新伤害重新取整，固定格挡扣除既定数值，防御状态条件使用防御完成时的快照；不再执行防御副作用，不再次抽牌或掷骰。
6. **潜水免伤**：先完成第5步的状态伤害公式和防御数值计算，再检查有效攻击颜色；潜水免疫蓝色攻击的全部本次命中伤害（含吸血），但不阻止状态施加。这里早于飞翔/守护，不消耗其层数，并且只反馈一次。
7. **特殊减伤**：玩家选择飞翔或守护，NPC按策略处理。飞翔失败后仍可选择守护。只对剩余正伤害消耗层数；不可防御表示跳过防御牌，仍允许特殊减伤。一次命中只处理一次特殊减伤。
8. **命中与收尾**：扣除生命，吸血按实际损失生命回血；然后提交 afterDamage（先伤害、后状态）的技能效果；此类新状态不参与本次攻击公式或特殊减伤。AOE各目标在自身扣血后提交对应效果，攻击者增益在整批命中结束后提交。随后处理防御出牌触发的既有流血、炸弹出牌计数、明确写为攻防结束后的效果、死亡与回合推进。

## 例外与边界

- 冷冻、沉睡等能否打防御牌，读取进入防御前已有状态。本次新施加状态不能追溯取消已经发生的防御。
- 潜水只免疫蓝色攻击伤害，不取消目标附带状态，也不替代防御技能的状态免疫。免疫/反弹不能误清攻击者获得的状态。
- 防御出牌触发流血时，只记录出牌前已有层数。本次新施加流血不追溯触发这次防御伤害。既有流血是独立伤害，不被守护对主攻击的完全格挡抹掉。
- 灼伤、中毒等独立状态伤害保持自己的触发规则，不自动当成可防御攻击。技能明确要求施加灼伤后立即结算时，该结算位于状态提交步骤。
- 判定牌、骰子结果、已消耗的牌与已选定分支锁定；状态重算不能再次判定或重新执行技能。
- 没有攻击伤害的纯效果技能直接提交效果并跳过防御。出牌阶段治疗、抽牌与资源操作保持其明确规则，不会为重算伤害而再次执行。

## 代码职责

- engine_attack.js：captureAttackSkill()记录待施加状态；prepareAttackSettlement()在防御后提交并重算；settlePreparedHit()执行统一命中。
- pendingSkillStatuses仅保存目标键、状态ID、操作方法、参数与timing（beforeDamage/afterDamage），不保存闭包。层数已满也记录施加意图，防御净化后可重新正确施加。
- pendingDamageFormula记录角色、牌值和预估伤害。角色damageAtSettlement()为无副作用公式；怪物注册桥用当前阶段的纯attackDamage()重算，翻牌/骰子伤害保留原结果。
- damageAfterDefense()只重算格挡数字（包括怪物阶段规则），不重放反击/抽牌/回血。
- pendingAttack.effectsPrepared、divingHandled/divingBlocked与avoidanceHandled分别保证前置效果、潜水和特殊减伤不重复；状态提交先移除队列项再执行。角色attackEffectTiming显式声明后置技能，不分析描述文本；未标记的旧快照默认beforeDamage。
- TurnMachine、1v2及领主适配器保留回合路由，主目标命中共用同一接口。整批命中收尾的performAttack调用显式携带commitAttackEffects；道具AOE、反击不能提前清空当前攻击的后置状态。
- 在线参与者交换同步映射pendingSkillStatuses.target。快照保存待施加状态与公式，刷新继续同一结算。

## 防御效果的当次结算

- 防御技能在该次防御内同步执行：出防御牌 → 按技能声明顺序提交状态、反击、恢复 → 重算攻击伤害 → 潜水/守护/飞翔 → 主攻击扣血。防御效果不加入待施加的攻击状态队列，也不延迟到下一回合。
- 所有注册角色/NPC的defend统一通过resolveDefenseSkill边界。常规状态方法已有事件时不再重复生成；直接状态赋值的旧技能在下一事件（例如恢复）之前补齐一次类型化状态事件。
- Vixraps防御2：先翻倍进攻方现有灼伤（上限5），先发出灼伤变化事件，再按翻倍后实际层数恢复生命；没有灼伤时不凭空新增，已达上限时不发送虚假的增加飘字。
- 防御效果事件携带目标与statusAfter。播放回血/伤害/状态时读取该事件快照，不提前显示整批后续最终状态。在线映射只变换目标键，状态快照仍属于同一事件目标。

## 判定牌展示生命周期

- 翻牌后保留判定牌面，供防御出牌、搭桥以及守护/飞翔选择时参照。整次防御结算结束后才移走；没有防御的纯效果分支在该次效果结束后移走。
- 实际入弃牌堆/手牌/牌库的时机不改变，展示副本不计入牌总数。来自判定区的弃牌事件携带 deferRevealExit，只延后动画；pendingJudgmentMoves 保存未播放的移动信息。
- 共用 finishJudgmentPresentation 发出 judgmentEnd，UI 按顺序播放延后的判定牌移动并清理牌面。普通手牌弃牌不延后。队列随快照保存，在线双方同时映射队列内的参与者键。

## 动画

事件顺序：攻击出牌→防御出牌/判定→前置状态反馈→伤害计算→潜水→特殊减伤判定→命中反馈→后置状态反馈。跳过防御也通过事件确认后执行主攻击扣血。

伤害/治疗事件携带hpBefore、hpAfter，播放使用当前事件的生命值，而非整批最终生命值。相同防御牌只在同次攻击内去重，下一张攻击重置去重键。缩短装饰性阅读等待，保留判定与玩家选择。
